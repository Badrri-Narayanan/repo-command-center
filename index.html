⌘ How to use Repo Command Center

What this is

A dashboard of every git repo in the folder shown at the top. Each tile is one repo. You can act on one repo from its tile, or select several repos and act on all of them at once.

A typical morning in 4 clicks

  1. Click the Behind chip to show only repos with new commits on the remote.
  2. Tick All visible or press a.
  3. Click ☀ Morning sync. It fetches, switches to the default branch, and fast-forward pulls.
  4. Check the tiles. Green = done, amber = skipped (with the reason), red = failed. Full git output is in the Activity log at the bottom.
The Behind count is only as fresh as the last fetch. Click ⇣ Fetch all first to get up-to-date counts.

Starting the app

Run python3 /path/to/server.py [FOLDER] on macOS, Linux or Windows (Python 3.9+ and git; nothing to install). FOLDER defaults to the current directory. Options: --depth N to find repos nested N folders deep (e.g. ~/code/<org>/<repo> → 2), --port N, --no-browser. Press Ctrl+C in the terminal to stop it.

Switching folders

Click the folder path at the top to open a different folder, change the search depth, or jump back to a recent folder.

Branch pill

⎇ mainOn the repo's default branch (detected from origin/HEAD, falls back to main/master).
⎇ feat/X-1On some other branch.
⎇ detached HEADNot on any branch. Pull is skipped.

Coloured left edge

Amber = behind or has uncommitted changes. Red = error or conflicts. The default sort (needs attention) puts these first.

Bottom lines

Last commit message, then hash · author · age · fetched X ago (the last time anything ran git fetch in that repo).

Pullgit pull --ff-only. Never creates merge commits. Fails cleanly if your branch has diverged.
→ mainSwitch to the default branch. Skipped if you have uncommitted changes.
Fetchgit fetch --all --prune. Updates ↓/↑ counts and doesn't touch your files.
Branch ▾Searchable list of local and remote branches, newest first. ● marks the current branch. Picking a remote-only branch creates a local tracking branch.
VS / Cu / IJOpen in VS Code / Cursor / IntelliJ IDEA. Only editors installed on this machine are shown. Add others (Sublime, PyCharm, Zed…) in ~/.repo-command-center.json; see the README.
GH / GL / BBOpen the repo on GitHub / GitLab / Bitbucket (from the origin remote).
⋯Stash (incl. untracked), Pop stash, Prune merged branches, every installed "open in" tool (file manager, terminal…), Copy path, PR/MR and CI links, Open PR for this branch, Refresh status.
☆Pin a repo so it always sorts to the top (remembered in this browser).
Prune merged branches deletes local branches already merged into the default branch, using git branch -d, which refuses unmerged work. Squash-merged branches aren't detected.

Selecting

  • Tick a tile's checkbox, or double-click empty space on a tile.
  • All visible / a selects every tile matching the current search and filter chip.
  • The Selected chip shows only your selection. Esc clears it.

Bulk buttons (enabled once something is selected)

☀ Morning syncfetch → switch to default → pull, per repo. Stops at the first step that fails or is skipped.
PullFast-forward pull on each repo's current branch.
→ Default branchSwitch every selected repo to its own default branch.
Checkout…Type a branch name (e.g. develop or feat/PROJ-123). Repos that don't have it are skipped.
FetchFetch the selection.
More ▾Stash, Pop, Prune, and open all selected repos in any installed editor, file manager or terminal.

Recipes

  • Get everything back on main: chip Off default → All visible → → Default branch.
  • Find forgotten work: chips Unpushed, Uncommitted, Has stash.
  • Work on one feature across several repos: search the ticket number (e.g. PROJ-123). The search matches branch names too.
  • Open related repos together: search a shared name part (e.g. billing) → select → More ▾ → Open in your editor.
Up to 6 repos run at once, each with its own spinner. A summary toast shows ok / skipped / failed counts at the end.

Status also refreshes when you come back to this tab after 30+ seconds away.

Safety

  • Pulls are fast-forward only. Nothing is merged or rebased behind your back.
  • Switching branches skips repos with uncommitted tracked changes (policy: SwitchPolicy in rcc/policy.py).
  • Git never waits for a password; it fails fast and the error shows on the tile.
  • The server only listens on 127.0.0.1 and needs a per-run token, so other websites can't send it commands.
